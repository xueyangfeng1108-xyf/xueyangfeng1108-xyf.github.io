Project Detail 01

AI Workflow Agent：邮件任务识别与日历自动化助手

使用 Make.com 集成 Gmail、Google Gemini 与 Google Calendar，搭建一个能够自动识别邮件任务、抽取结构化字段、过滤无效信息并创建日历事件的 AI Workflow Agent 原型。

查看 Make 公开场景 查看 GitHub 项目说明

Problem

在日常学习和工作场景中，用户经常通过邮件接收会议、截止日期、任务提醒和待办事项。但这些信息分散在不同邮件中，需要人工阅读、判断、复制时间地点并手动创建日历事件。该流程重复性高，且容易遗漏重要事项。

Goal

验证端到端 AI 自动化流程是否可行：当邮件包含明确任务和时间信息时，系统按固定格式抽取优先级、任务名、开始时间、结束时间和详情；当邮件不包含任务或信息不足时，输出 ignore，避免误创建事件。

User Pain Points

  • 邮件信息量大，容易漏掉任务和截止日期
  • 邮件里的任务信息格式不统一
  • 手动创建日历事件耗时
  • 普通关键词规则难以判断真实任务
  • AI 可能误识别无关邮件，需要过滤规则

Workflow

Gmail 新邮件 Make.com 触发 Gemini 分析 字段抽取 有效任务判断 Calendar / ignore

My Role

  • 负责 AI Workflow Agent 原型设计
  • 使用 Make.com 设计自动化流程
  • 设计 Gmail、Gemini、Google Calendar 集成逻辑
  • 编写结构化 prompt 和 ignore 过滤规则
  • 进行端到端测试并总结验证结果

AI Design

输入邮件正文、主题、发件人、时间
AI 判断是否包含明确任务、会议、截止日期或待办事项
字段抽取优先级、任务名、开始时间、结束时间、详情
过滤规则非任务类邮件、信息不完整邮件输出 ignore
执行动作创建 Google Calendar 事件

Testing / Outcome

使用 10 封测试邮件进行端到端验证，系统成功识别出 4 个有效事项，并创建了 4 个 Google Calendar 事件。测试结果证明该自动化流程在小样本场景下具备可行性。

Reflection & Next Iteration

  • 信息不完整时不应自动创建事件
  • 对“下周五下午”等模糊时间增加用户确认
  • 加入 human-in-the-loop 审核节点
  • 增加失败日志、异常提醒、优先级分类
  • 扩展到 Slack、Notion、Todoist 等工具

Project Detail 02

Telegram AI Translation Bot：基于 n8n 与 Gemini 的自动翻译机器人

使用 n8n 搭建 Telegram AI 翻译 Bot，让用户在聊天界面中直接发送文本并获得结构化翻译结果。

Problem

跨语言沟通中，用户不仅需要知道字面意思，也需要保留语气、习语、上下文和文化含义。传统翻译工具偏向单次文本转换，缺少对对话场景的持续处理。

Goal

探索 AI 翻译能力在即时通讯场景中的产品化可能，让用户在 Telegram 对话中直接发送文本并获得可读、可解释的翻译结果。

Workflow

Telegram 消息 Telegram Trigger n8n 读取输入 Gemini 翻译 AI Agent 格式化 自动回复

Prompt / Agent Logic

Role跨语言翻译助手
Task自动检测输入语言并翻译
Rules保留语气，不逐字硬翻
Idiom Handling识别习语并输出自然表达
Safety不添加用户没有表达的含义

Output Format Example

Target Language: Chinese

Translation:
...

Tone:
Informal / Polite / Sarcastic / Neutral

Cultural Note:
如果存在习语或文化表达，在此解释。

Product Value

  • 将 AI 翻译嵌入用户原本的聊天场景
  • 降低跨语言沟通中的工具切换成本
  • 通过固定格式提高翻译结果可读性
  • 通过语气和习语识别增强翻译质量

Next Iteration

  • 增加目标语言选择按钮
  • 增加翻译历史记录
  • 支持群聊中的自动翻译

  • 增加商务、法律、学术、旅游术语表

Project Detail 03

Cultural Translation Agent：基于 Claude Projects 的跨文化语义翻译智能体

使用 Claude Projects 设计文化翻译 Agent，通过 Agent 指令和 prompt 规则提升跨文化语义翻译质量。

Problem

跨文化翻译不仅是语言转换，更涉及语境、语气、习语和文化含义的理解。许多 AI 翻译结果虽然字面准确，但可能丢失讽刺、礼貌程度、情绪强度或文化隐含信息。

Design Goals

  • 支持英文、中文、Hindi 之间的语义翻译
  • 识别习语、成语和跨文化表达
  • 保留原文语气，避免逐字翻译
  • 通过回译验证检查含义是否偏离

Agent Design Framework

Role跨文化语义翻译 Agent
Goal保留语义、语气和文化含义
Skills语言检测、习语识别、语气分类、语义翻译、回译验证
Rules不逐字硬翻，不添加原文没有的信息
Feedback Loop根据测试结果迭代 prompt
Output Format翻译结果 + 语气说明 + 文化解释 + 回译检查

Meta-prompting Iteration

初版问题

翻译结果偏直译，对习语和讽刺语气处理不足。

迭代方式

通过 meta-prompting 要求模型反思翻译失败原因，并生成更明确的 Agent 行为规则。

优化后规则

先判断习语、讽刺或文化表达，再判断语气；翻译时优先保留语义和语气，并用回译验证检查偏离。

Testing Method

英文习语观察是否避免逐字翻译
中文成语观察是否保留文化含义
讽刺语气观察是否识别真实语气
跨文化表达观察是否解释文化差异

Productization

  • 留学生跨文化沟通助手
  • 国际团队邮件润色
  • 客服跨语言沟通
  • 本地化内容审核
  • 可与 Telegram Bot 结合成完整翻译产品

AI Product Sense

我的 AI 应用设计原则

01

不为了 AI 而 AI

AI 应该解决真实用户问题，而不是作为装饰功能存在。

02

事实提取和内容生成分开

高风险内容中，事实字段必须来自原始输入，生成内容应标注为建议。

03

AI 输出必须可编辑、可撤回、可重生成

用户需要保留最终控制权，尤其是在沟通、日程和内容发布场景。

04

信息不足时不要自动执行

日期、时间、对象或任务不完整时，应输出 ignore 或请求用户确认。

05

高风险内容需要 human-in-the-loop

涉及法律、隐私、品牌、商业决策和用户个人信息时，需要人工复核机制。

06

Prompt 是产品规则的一部分

Prompt 不只是模型指令，也是产品逻辑、边界、格式和风险控制方式。

07

评估 AI 不能只靠主观感觉

需要通过准确性、相关性、可用性、可信度、可控性和效率等维度评估。

08

Agent 需要反馈循环

Agent 不应该只执行一次任务，而应通过测试、反馈和规则迭代持续优化。
