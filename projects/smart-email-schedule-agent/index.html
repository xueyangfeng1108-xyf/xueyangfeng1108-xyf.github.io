AI Workflow Agent / Make.com / Gmail / Gemini / Google Calendar

智能邮件日程助手 Agent

这是一个将 Gmail 中的会议、截止日期和待办提醒识别为 Google Calendar 事件的 AI 工作流原型。 我围绕邮件日程管理场景，设计了任务识别规则、结构化输出格式、自动化字段映射和误执行防护机制，让 AI 能在清晰边界内完成可落地的工作流动作。

Problem Framing

从“邮件很多”到“哪些邮件值得自动执行”

用户问题

任务信息分散，人工整理成本高

会议、截止日期、系统提醒和临时待办经常散落在邮件中。用户需要逐封判断是否需要行动，再手动复制标题、时间和详情到日历，过程重复且容易漏掉。

产品挑战

不能只追求“自动化”，还要避免误执行

邮件中出现日期不代表它一定是任务。如果 Agent 随意推断时间或创建错误事件，反而会打扰用户。因此这个原型把“什么时候不执行”设计为核心规则。

产品判断： 日历创建属于高影响动作，Agent 应该先识别意图和信息完整度，再决定执行或忽略，而不是把所有含时间的邮件都转成事件。

Current Journey

原本的人工流程

1. 打开邮件阅读完整上下文
2. 判断行动确认是否真的需要处理
3. 提取信息找出标题、日期和时间
4. 切换工具打开 Google Calendar
5. 创建并核对手动录入事件详情
设计机会： 这个流程的痛点不只是“慢”，而是用户需要持续做重复判断和跨工具切换。Agent 的价值在于把高频、低创造性的判断与录入步骤自动化，同时保留必要的安全边界。

Product Goal

原型目标

识别

判断邮件是否包含任务

让 Gemini 根据邮件标题与正文判断是否存在明确待办、会议、提醒或截止日期。

结构化

输出可被系统读取的字段

要求模型按固定格式返回优先级、任务名、开始时间、结束时间和详情，减少后续模块解析成本。

执行

只对有效事项创建日历

当结果为 ignore 时不进入日历创建；当信息完整时才映射到 Google Calendar。

Workflow Design

Agent 工作流

1. Gmail搜索候选邮件，读取标题和正文
2. Gemini判断是否存在明确任务
3. 输出约束无任务返回 ignore，有任务返回固定格式
4. Make 解析用换行拆分结果并映射字段
5. Calendar创建 Google Calendar 事件

Integration Detail

自动化映射设计

模块 输入或动作 产品设计意图
Gmail Search emails 读取邮件 Subject 与 Full text body 优先使用用户真实邮件文本，避免让模型凭空生成上下文。
Google Gemini AI 根据邮件内容输出 ignore 或固定格式任务 把“判断”和“结构化”合并为一步，让后续自动化模块更容易处理。
Make.com 函数 使用 split / get 按换行提取结果行 将自然语言输出转换为可映射字段，例如事件名称取第一行。
Google Calendar 创建 In Detail 类型日历事件 只在输出可解析且包含时间信息时进入执行动作。

Product Value

从个人效率到可复用的 Agent 模式

直接价值
  • 减少手动阅读、复制和创建日历的重复操作。
  • 把隐藏在邮件正文里的承诺、截止日期和会议提醒转成可见日程。
  • 通过固定输出和 ignore 规则降低误创建事件的概率。
可复用模式
  • Trigger：从业务系统捕捉候选信息。
  • Classify：判断是否值得进入下一步。
  • Extract：抽取可执行字段。
  • Act：在规则允许时完成自动化动作。

Responsible AI

风险边界与下一步优化

当前边界
  • 不公开 Gmail 内容、Google 连接、Gemini 密钥或 Make 凭据。
  • 无任务或信息不完整时返回 ignore，不创建日历事件。
  • 输出格式必须固定，减少下游解析失败。
下一步
  • 增加创建日历前的人工确认步骤。
  • 增加高、中、低置信度标签。
  • 对“下周五下午”等模糊时间触发二次确认。
  • 记录 ignore 原因和创建失败原因，形成可复盘的运营看板。
