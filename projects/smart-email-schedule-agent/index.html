Project 03 / Make.com + Gmail + Gemini + Google Calendar

智能邮件日程助手 Agent

这是一个将 Gmail 中的会议、截止日期和待办提醒识别为 Google Calendar 事件的 AI Workflow 原型。我围绕邮件日程管理场景，设计了任务识别规则、结构化输出格式、字段映射和误执行防护机制。

Problem Framing

从“邮件很多”到“哪些邮件值得自动执行”

用户问题

任务信息分散，人工整理成本高

会议、截止日期、系统提醒和临时待办经常散落在邮件中。用户需要逐封判断是否需要行动，再手动复制标题、时间和详情到日历，过程重复且容易漏掉。

产品挑战

不能只追求自动化，还要避免误执行

邮件中出现日期不代表它一定是任务。如果 Agent 随意推断时间或创建错误事件，反而会打扰用户。因此这个原型把“什么时候不执行”设计为核心规则。

产品判断：日历创建属于高影响动作，Agent 应该先识别意图和信息完整度，再决定执行或忽略，而不是把所有含时间的邮件都转成事件。

Current Journey

原本的人工流程

1. 打开邮件阅读完整上下文。
2. 判断行动确认是否真的需要处理。
3. 提取信息找出标题、日期和时间。
4. 切换工具打开 Google Calendar。
5. 创建并核对手动录入事件详情。

Workflow Design

Agent 工作流

1. Gmail搜索候选邮件，读取标题和正文。
2. Gemini判断是否存在明确任务。
3. 输出约束无任务返回 ignore，有任务返回固定格式。
4. Make 解析用换行拆分结果并映射字段。
5. Calendar创建 Google Calendar 事件。

Integration Detail

自动化映射设计

模块输入或动作产品设计意图
Gmail Search emails读取邮件标题与正文。优先使用真实邮件文本，避免模型凭空生成上下文。
Google Gemini AI根据邮件内容输出 ignore 或固定格式任务。把“判断”和“结构化”合并为一步，让后续自动化模块更容易处理。
Make.com 函数使用 split / get 按换行提取结果行。将自然语言输出转换为可映射字段，例如事件名称取第一行。
Google Calendar创建 In Detail 类型日历事件。只在输出可解析且包含时间信息时进入执行动作。

Result / Evidence

Product Thinking

从个人效率到可复用的 Agent 模式

直接价值
  • 减少手动阅读、复制和创建日历的重复操作。
  • 把隐藏在邮件正文里的承诺、截止日期和会议提醒转成可见日程。
  • 通过固定输出和 ignore 规则降低误创建事件的概率。
风险边界
  • 不公开 Gmail 内容、Google 连接、Gemini 密钥或 Make 凭据。
  • 无任务或信息不完整时返回 ignore，不创建日历事件。
  • 后续可增加人工确认、置信度标签和模糊时间二次确认。
