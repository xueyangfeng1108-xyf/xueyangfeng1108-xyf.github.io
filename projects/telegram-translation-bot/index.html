Project 01 / n8n + Telegram + Gemini

Telegram AI 翻译 Bot

将跨文化翻译 Agent 接入 Telegram 聊天场景，让用户直接在熟悉的聊天界面里发送中文或英文消息，并收到自动翻译、语气判断和习语处理结果。

Bot 原型 Workflow 自动化 Prompt 规则 边界测试
效果证据：网络用语与中文成语被转化为自然表达，并输出语气与习语判断。

Problem Framing

把翻译能力放回真实聊天场景

用户问题

翻译工具和聊天场景割裂

用户在聊天中遇到外语、中文网络用语或职场习语时，通常需要复制到另一个翻译工具，再切回聊天窗口。这个过程打断沟通，也容易丢失上下文。

产品挑战

翻译不只是语言转换

中文和英文里的习语、成语、讽刺、玩笑和无奈语气都不能逐字处理。Bot 需要先判断语言和含义，再决定目标语言中的自然表达。

产品判断：聊天 Bot 的价值不是“多一个翻译入口”，而是降低切换成本，并让 AI 在用户原有行为流里完成判断、翻译和自动回复。

Workflow Architecture

Trigger → Logic → Action 三段式工作流

1. Telegram 消息用户向 Bot 发送中文或英文消息。
2. Telegram Triggern8n 接收消息文本、发送者 chat ID 和元数据。
3. AI Agent + Gemini读取 {{ $json.message.text }}，按系统规则翻译。
4. Telegram 自动回复通过 chat ID 将 {{ $json.output }} 回传给正确用户。

Integration Detail

关键配置与产品意图

模块关键配置设计意图
Telegram Trigger监听 Message 类型输入。只处理文字消息，避免图片、文件等非目标输入干扰原型测试。
AI Agent + Gemini用户消息字段映射为 {{ $json.message.text }}。保证模型处理真实用户输入，而不是空 prompt 或测试文本。
系统规则先识别语言，再判断习语/成语和语气，最后输出目标语言。把翻译任务拆成可解释的 Agent 行为步骤。
Send Messagechat ID 来自触发节点，回复内容来自上一步输出。确保多人使用时，回复回到对应发送者，而不是固定账号。
发布与运行workflow 发布后由 n8n 云端运行。Bot 不依赖本地窗口在线，更接近可分享的产品原型。

Agent Rules

翻译 Agent 行为规则

语言判断

中英双向翻译

中文输入翻译为英文，英文输入翻译为简体中文；遇到非中英文输入时给出支持范围提示。

习语 / 成语

先理解含义再翻译

把 yyds、绝绝子、画大饼、push came to shove 等表达当作非字面语言处理。

语气保留

输出可被评估

在结果中标注语气和是否包含习语，方便观察模型是否理解了真实情绪。

Testing Evidence

从正常输入到边界输入的测试设计

测试思路：先验证主路径可用，再主动寻找系统边界。第三语言、混合语言、网络用语和多习语长句都属于需要提前发现的异常输入。

Product Thinking

产品价值与下一步

用户价值
  • 降低翻译工具和聊天工具之间的切换成本。
  • 让习语、成语和语气判断显性化，输出更容易评估。
  • Bot 形态适合朋友、同学或小团队快速试用。
下一步优化
  • 增加语言选择和用户偏好记忆。
  • 加入反馈按钮，用“翻译准确 / 语气不自然 / 习语错误”沉淀测试数据。
  • 记录失败输入，形成 prompt 迭代日志。
  • 对敏感、冒犯或高风险文本增加人工复核提醒。
